## Вывод

Основное направление — помочь человеку найти русскоязычное сообщество Assetto Corsa Competizione, выбрать подходящую гонку и пройти путь до первого участия. Для ASG это перспективнее, чем продвижение по одному широкому слову «ACC» или массовое создание однотипных страниц.

Сначала следует улучшить исходный HTML важных страниц и адреса отдельных сущностей. Затем — усилить инструкции, описание сообщества, расписание и полезные материалы на основе собственных правил и результатов. Эти же материалы смогут служить источниками для ответов поисковых ИИ.

Изучены публичная выдача по русским и английским запросам, обсуждения игроков, сайты сообществ и карточки соревнований, официальные рекомендации Google, Яндекса, OpenAI и Bing. Дополнительно проверены исходники канонического репозитория `top` и ответы десяти публичных URL ASG.

Ниже не используются выдуманные объёмы поиска. Порядок работ определяется соответствием ASG и близостью к участию в гонке.

Проверка исходного HTTP-ответа, без выполнения JavaScript:

| `/clubs/?slug=asg-racing` | 200 | `https://asgracing.ru/clubs/` | Общий H1 сообщества |

Также проверены `/about/`, `/teams/`, `/news/`: HTTP 200, исходный H1 общий. Полный локальный результат: `C:/Python/asgracing/tmp/seo-public-audit-20261008.json`.

1. **Базовая инфраструктура есть.** `robots.txt` разрешает обход, sitemap содержит 36 URL RU/EN. Присутствуют route-level title/description, canonical, hreflang и базовая разметка WebSite/Organization.
2. **Основное содержимое подстраниц появляется после JavaScript.** Исходный HTML содержит общую оболочку главной; `/en/` также содержит русский исходный H1. Контроллер после загрузки данных меняет содержимое и часть метаданных. Это не доказательство отсутствия индексации, но ограничение для роботов, которые не исполняют JS, и повод проверить отрендеренные страницы в кабинетах поисковиков.
3. **Canonical сущностей теряет идентификатор.** Проверенные страницы разных пилотов/клубов сообщают адрес общего шаблона. Генератор SEO формирует canonical из пути без query. Найденная функция `canonicalEntityHref` перенаправляет старые ссылки новости/гонки, но не устанавливает уникальный SEO-canonical для каждой сущности.
4. **В sitemap нет инвентаря отдельных сущностей.** Наличие ссылки на каталог не заменяет перечисление выбранных полезных новостей, сезонов и клубов. Не нужно добавлять пустые шаблоны или все фильтры/пагинацию.
5. **Нужна проверка `/join/` и `/instructions/`.** Их источники используют одно руководство начала участия. Следует сравнить итоговый контент и выбрать отдельные задачи страниц либо основной адрес с сохранением старых переходов.

Google умеет обрабатывать JavaScript, но рекомендует предварительную генерацию HTML; не все роботы выполняют JS. Яндекс выбирает рендеринг с учётом собственных настроек и решения робота. [Google: JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [Яндекс: индексирование JavaScript](https://yandex.ru/support/webmaster/ru/yandex-indexing/rendering).

## Порядок доработок без изменения игрового бэкенда

### Этап 1. Полезный исходный HTML

- При сборке подставлять реальные H1, вводный текст и основное статическое содержание `/about/`, `/instructions/`, `/hourly/`, `/championships/`, `/teams/` и их английских вариантов.
- Сохранить макет V2, интерактивность, подключение текущих JSON, ленивую загрузку тяжёлых таблиц. Для инструкции не требуется загрузка статистики всего сайта.
- Перенести содержательные тексты в единый поддерживаемый источник, используемый сборкой и интерфейсом. Не править вручную сгенерированные `index.html`.
- Сохранить действующие счётчик Метрики, verification-теги, языковые связи и совместимость ранее опубликованных адресов.

Точки реализации: `v2/page-registry.js`, генераторы страниц/SEO, `scripts/build-root-seo.mjs`, `v2/pages/views/information.js`, `v2/pages/controller.js`.

### Этап 2. Индексация отдельных страниц

- Для каждой индексируемой сущности выбрать собственный стабильный URL, title, description, canonical, языковые связи и основной HTML.
- Начать с актуальных сезонов, новостей, клубов и команд; профили пилотов и старые результаты — после оценки полезности и публичности данных.
- Параметр `id` или `slug` сам по себе не мешает SEO. Проблема — общий canonical и одинаковый исходный шаблон для разных сущностей.
- Обычный статический файл не может выдавать разный HTML только по query. Для полноценной генерации потребуется согласовать отдельные пути файлов/страниц и совместимые переходы со старых query-адресов либо возможности текущего хостинга. Замена canonical только в JS — ограниченный промежуточный вариант.
- Снимки страниц можно собирать из уже публикуемых JSON. Нужны расписание обновления, дата актуальности, сохранение последнего корректного снимка при ошибке данных и проверка отсутствия приватных полей. Игровой Python-бэкенд менять не требуется.
- В sitemap включать только готовые содержательные URL. Проверить реальные 301, отсутствие цепочек переходов, корректные 404 для отсутствующих сущностей, статус старой версии и отсутствие дублей `/preview`.

### Этап 3. Контент, который приводит пилотов

Сначала улучшить существующие страницы:

- **Главная:** кратко объяснить, для кого ASG, какие доступны форматы и куда идти для первого участия. Развёрнутые объяснения оставить на соответствующих страницах; не добавлять большой текст над текущими карточками.
- **О сообществе:** фактические форматы, платформа, язык общения, часовой пояс, официальные контакты, кто помогает с вопросами, ссылки на результаты и правила.
- **Инструкция:** как найти сервер по точному названию, войти через Steam, проверить допуск, выбрать событие и записаться. Разделить игровой SA и собственный SR ASG.
- **Часовые гонки:** описание формата, актуальное расписание, часовой пояс, требования и ссылка на полные условия события. Не фиксировать единый порог SR, если серверы требуют разный рейтинг.
- **Чемпионаты:** текущий сезон, реальные даты, регламент, порядок участия; завершённые сезоны сохранить с понятным статусом и результатами.
- **Клубы и команды:** состав, результаты и доступный официальный способ связаться. Не обещать набор в команду, если такого статуса нет в данных.

Первая очередь новых содержательных материалов:

1. Как начать гонять в ASG Racing: от установки ACC до первой гонки.
2. SA в ACC и Safety Rating ASG: различия, требования и выбор сервера.
3. Как меняется SR ASG: чистота, невалидные круги, инциденты и автоштрафы, с проверяемыми примерами.
4. Как подготовиться к часовой гонке: расписание, регламент, топливо и питстоп.
5. Как присоединиться к клубу или найти команду в ASG.
6. Как безопасно пройти старт в Monza: собственные примеры, иллюстрации или видео.

Не публиковать тысячи автоматических страниц «машина × трасса» с одинаковым текстом. Материалы должны опираться на реальные правила, результаты и опыт сообщества, иметь автора/ответственного и дату существенного обновления. Новости гонок связывать с сезоном, результатами и инструкцией участия обычными HTML-ссылками.

## Как улучшить представление в поисковых ИИ

Практическая цель — чтобы на вопрос «где гонять в ACC новичку вечером по Москве?» можно было дать точный ответ со ссылкой на ASG.

На основных страницах нужны короткие самостоятельные ответы и таблица проверенных фактов: полное название игры, платформа, язык общения, форматы, часовой пояс, требования конкретного формата, порядок записи и контакты. У изменяемых сведений — дата актуальности и ссылка на первоисточник внутри сайта.

Предлагаемые вопросы для FAQ:

- Подходит ли ASG человеку без опыта онлайн-гонок?
- Какая версия игры и платформа нужны?
- Как найти сервер ASG в ACC?
- Чем игровой SA отличается от SR ASG?
- Какой рейтинг нужен для выбранного сервера?
- Когда проходят гонки и в каком часовом поясе?
- Как записаться и отменить запись?
- Где посмотреть требования DLC и регламент питстопа?
- Как выбрать клуб или команду?
- Куда обратиться за помощью или подать жалобу?

Ответы размещать в доступном HTML и писать только по подтверждённым правилам. FAQ полезен как содержание; наличие FAQ-разметки не даёт гарантии расширенного поискового результата.

Технически Google не требует отдельного «AI SEO» файла или особой разметки для AI Overviews/AI Mode. Основой остаются индексируемые полезные страницы. [Google: AI features and your website](https://developers.google.com/search/docs/appearance/ai-features).

Для ChatGPT Search важен доступ `OAI-SearchBot`. `GPTBot` отвечает за возможное использование для обучения и управляется независимо. Текущий `Allow: /` уже разрешает обход; нужно проверить фактическую доступность страниц и защиту хостинга, а не просто добавить ещё одну разрешающую строку. [OpenAI: описание роботов](https://developers.openai.com/api/docs/bots).

Разметку Organization дополнить реальным логотипом и официальными `sameAs`; для подходящих страниц добавить BreadcrumbList, Article и сведения о событиях. Разметка должна совпадать с видимыми данными. Для виртуальных гонок отдельно проверить применимость требований Event: не выдумывать физическое место проведения ради расширенного результата.

В официальных Telegram, Discord, Steam и видеоканалах использовать согласованное название ASG Racing, описание и ссылку на сайт. Рассмотреть содержательные руководства и реальные карточки событий на подходящих площадках. Это рекомендации по присутствию; публикации и сообщения сторонним сообществам в рамках исследования не отправлялись.

## Проверка результата

1. Получить запросы и страницы за последние 90 дней из Google Search Console и Яндекс Вебмастера. Отдельно анализировать бренд ASG, небрендовые запросы, RU/EN и устройства.
2. Проверить кандидаты в Wordstat: варианты игры, регион, динамику и уточняющие слова. После этого выбрать основные формулировки заголовков. [Wordstat: официальная инструкция](https://www.yandex.ru/support/direct/ru/keywords/wordstat).
3. Перед выпуском сравнить исходный и отрендеренный HTML, canonical, hreflang, sitemap, статусы URL и основные переходы. Проверить несколько страниц через инструменты поисковиков; публичный HTTP 200 сам по себе не доказывает индексацию.
4. После выпуска сравнивать сопоставимые периоды по 28 дней: видимость, небрендовые клики, CTR и переходы к участию. Учитывать сезонность, смену версии сайта и календарь гонок.
5. В существующей Метрике отслеживать путь «поиск → инструкция/расписание → вход → успешная запись». Запись считать после подтверждения операции, а не только по нажатию кнопки. Переход в Telegram/Discord не равен фактическому вступлению. Для этого проекта установка Google Analytics не является обязательным условием.
6. Раз в месяц повторять одинаковый набор вопросов в доступных поисковых ИИ, записывая язык, дату, условия и процитированные URL. Результаты могут меняться; не считать один ответ устойчивой позицией.
7. Рассмотреть Bing Webmaster Tools: AI Performance показывает цитирование в поддерживаемых продуктах Microsoft и отдельных партнёров. Это не универсальный отчёт обо всех ИИ. [Bing: AI Performance](https://blogs.bing.com/webmaster/2026/2/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview).

## Рекомендуемая первая итерация

Подготовить правильный исходный HTML для главной, инструкции, сообщества и часовых гонок, включая EN; уточнить canonical сущностей и способ генерации отдельных страниц; затем дополнить инструкцию и объяснение SA/SR. Дальнейшее расширение контента выбирать по реальным поисковым запросам и конверсиям.

Завершение исследования не означает изменение robots, публикацию страниц, подключение дополнительных сервисов или изменение серверных правил. Появление ASG в рекомендациях ИИ и рост поискового трафика не гарантируются.
