Дата: 03.10.2026, Europe/Moscow.

## Цель

Подготовить ASG Lab к распространению через сайт: реальная демонстрация продукта → Steam-аккаунт → скачивание EXE с VPS → покупка периода → активация приложения → управление подпиской и обновлениями.

Главный критерий запуска: подтверждённая оплата приводит к работоспособному доступу в настоящем приложении. Проверка заканчивается работающим оверлеем в ACC, а не успешным ответом API или записью ключа в базе.

## Исходное состояние и границы

- `/asg-lab/` существует как переход на защищённый макет auth-сервиса. Исходники: `top/asg-lab/index.html`, `asg-auth/asg_auth/lab_preview.py`, `asg-auth/asg_auth/lab_preview_assets`.
- Текущий доступ — только владелец и технический директор, с серверной проверкой Steam-аутентифицированной сессии. Будущий доступ всем Steam-пользователям — отдельная задача; гости страницу продукта не получают.
- Макет содержит условные оверлеи, три периода, служебные подписи, незаполненные реквизиты; реальные оплата и скачивание отключены.
- Готовность API приложения, ключей и обновлений не установлена. Их канонические исходники необходимо определить в начале интеграции; локальный broadcast-прототип не считается ASG Lab.
- Кабинет, подписки и оплата ранее отложены. Здесь они планируются; их реализация требует отдельной задачи.
- Приложенный frontend-документ — источник требований к дизайну. Он не разрешает сейчас менять URL на `/ru/asglab/`, открывать доступ, объявлять продукт Alpha или выполнять весь приведённый workflow.

## Этап 1. Доработка фронтенда — P0

- Верхняя панель: согласовать с общим сайтом, показать корректный активный раздел, аккаунт/Steam-вход, RU/EN, мобильное меню; сохранить favicon и логотип → `/ru/`.
- Hero и каталог: заменить условные виджеты реальными снимками. Сверить Standings, Relative, Delta, Telemetry, Session, Weather и дополнительные виджеты с готовыми функциями.
- Cockpit: использовать реальный интерфейс приложения; демонстрационные переключатели не выдавать за управление установленной программой.
- «Настрой экран под себя»: RACE / QUALIFY / MINIMAL показывают реальные варианты оверлеев в ACC. Начать с переключения снимков; drag-and-drop добавлять только при отдельной необходимости.
- Тексты: удалить «Закрытый концепт», «доступ команде проекта» и внутренние `CONCEPT` / `DEMO`. Сохранить честные состояния «релиз готовится» и «оплата недоступна», пока сервисы не подключены.
- Тарифы: четыре карточки — месяц / 3 месяца / полгода / год. Полные цены и скидки подключаются после утверждения, а не берутся из примеров переписки.
- Скачивание/обновления: подготовить состояния данных релиза, загрузки, отсутствия версии и ошибки. Пока нет действующего API — локальные фикстуры, без запросов к выдуманным endpoints.
- Реквизиты/документы: подготовить отображение утверждённых сведений, доступные ссылки и независимые элементы принятия условий.

Необходимые материалы: игровой Hero, снимки каждого готового виджета, Cockpit, три реальные раскладки и, при наличии, видео. Зафиксировать версию приложения на материалах. Не подменять недостающие реальные изображения генерацией вымышленного интерфейса.

Приёмка: 360/375/430/768/1024/1440/1920 px, RU/EN, клавиатура и focus, читаемость, отсутствие переполнения, загрузка медиа по необходимости. Проверить 401 гостю, 403 постороннему аккаунту, доступ двум разрешённым аккаунтам, включая ресурсы страницы.

Важно: макет сейчас обслуживается с auth-домена, а кабинет — с основного сайта. До подключения общего хедера и API проверить origin, сессии, CSP и разрешённые обращения. Не ослаблять политики остальных auth-маршрутов ради страницы.

## Этап 3. Проверка и установка обновлений — P0

Разделить на две подзадачи:

**3а. Обнаружение версии.** Приложение проверяет метаданные при запуске и по кнопке; периодический интервал определить отдельно. Сайт и кабинет используют тот же источник сведений. Сравнивать версии корректно, учитывать архитектуру, минимальную версию и совместимость; отсутствие сети обрабатывать без ложного «подписка истекла».

**3б. Установка.** Скачивать во временное место, проверять целостность и доверенную подпись, устанавливать после закрытия затрагиваемых процессов через отдельный updater/bootstrap. Updater живёт вне заменяемого payload. Не прерывать сессию игры автоматической установкой; пользователю предлагается подходящий момент.

Сохранять настройки и пользовательские раскладки. Предусмотреть health-check после установки, откат и совместимость настроек; миграции состояния требуют отдельной схемы резервирования и восстановления. Хеш с того же VPS не заменяет доверенную подпись.

Приёмка: версия уже актуальна; доступна новая; сеть оборвалась; файл повреждён; подпись неверна; недостаточно места; приложение запущено; установка не удалась; новая версия не прошла health-check; восстановлена предыдущая рабочая версия. Отдельно проверить, что лицензия переживает разрешённое обновление без повторной покупки.

## Этап 4. Steam, активация и API доступа — P0

- Права относятся к стабильному внутреннему аккаунту ASG, связанному со Steam. Driver ID остаётся публичным идентификатором.
- Дописать проверенную существующую реализацию: создание тестового права, активация, проверка состояния, срок, продление, истечение, отзыв, устройства и замена ПК.
- Предпочтение для проектирования: активация из кабинета через короткоживущий одноразовый код/подтверждение; постоянный ключ использовать только если он нужен реальному приложению и согласована его безопасная выдача.
- На сервере проверять владельца каждой подписки, устройства и операции. Повторные запросы обрабатывать без выдачи второго права; секреты не выводить в журналы.
- Согласовать офлайн-политику и восстановление после сбоя. Недоступность сервиса, отсутствие права и необходимость обновления — разные состояния.

Приёмка до оплаты: настоящая копия ASG Lab работает с активным тестовым правом, корректно обрабатывает чужую активацию, истечение, отзыв, превышение устройств, продление, переустановку и сбои связи.

## Этап 6. Оплата в закрытом тестовом режиме — P0

5. При сбое выдачи обеспечить повторную обработку, мониторинг и понятное сообщение покупателю; повторной оплаты не требовать.

Приёмка: успешная оплата → кабинет → активация → работа оверлея; отмена/неуспех; двойной клик; задержка/дубль/подделка уведомления; закрытая вкладка; оплата прошла, API временно недоступен; сверка без webhook; продление; возврат. ## Этап 7. Контролируемый выпуск

- Закрыть блокирующие дефекты, утвердить цены/условия и эксплуатационные процедуры.
- Для каждого компонента отдельно подготовить версию, состав изменения, проверки и откат: сайт `top/main`, auth/API на VPS, сервис/артефакт релизов, Windows-приложение.
- По отдельному разрешению открыть `/asg-lab/` всем Steam-аутентифицированным пользователям; серверную проверку сохранить для HTML и ресурсов. Юридические документы имеют отдельно определённые маршруты доступности.

Блокируют продажи: приложение не проходит активацию; права/продавец не определены; цены/документы/реквизиты не утверждены; отсутствуют чеки/возвраты; доступ выдаётся по браузерному redirect; не проверены повторные события и восстановление ошибок; подписка и приложение расходятся по состоянию.
